Tahap 1: Fondasi frontend
Buat project frontend (Vue 3, Vite, Tailwind, Vue Router, Axios), lalu atur FRONTEND_URL untuk CORS.
Layout dasar: navbar, footer, tampilan responsif HP dan laptop, semua teks berbahasa Indonesia.
Identitas visual: warna dan logo toko. Saya butuh logo dan referensi dari wireframe Anda.
Lapisan API: base URL dari .env, penanganan error 401/422/429, dan halaman error/memuat.
Data contoh: jalankan ProdukContohSeeder agar halaman bisa dicoba.
Tahap 2: Sprint 1, Company Profile dan Katalog (UC-01, UC-03, UC-04)
Beranda (KF-01, KF-02): profil usaha, keunggulan, kategori, kontak WhatsApp, dan tombol ke katalog (satu klik).
Katalog (KF-03): grid produk aktif dengan foto, nama, harga, pagination, dan pesan “produk belum tersedia” bila kosong.
Cari, filter, urut (KF-04 s.d. KF-06):
Cari berdasarkan nama, filter kategori dan rentang harga, urut harga dan terbaru.
Validasi harga min > maks, dan pesan “Produk tidak ditemukan” dengan tombol hapus filter.
Target tampil < 3 detik (KNF-01).
Tahap 3: Sprint 2, Detail, WhatsApp, Shopee, Kontak (UC-02, UC-05, UC-06, UC-07)
Detail produk (KF-07): foto, nama, kategori, harga, ukuran, deskripsi. Produk nonaktif atau terhapus menampilkan “Produk tidak tersedia” dan tautan kembali.
Tombol “Pesan via WhatsApp” (KF-08): pakai whatsapp_url dari API. Tombol disembunyikan bila nomor kosong.
Tombol “Beli di Shopee” (KF-09): disembunyikan bila tautan kosong.
Halaman Kontak dan Lokasi (KF-10): alamat, tautan Instagram, WhatsApp, dan Shopee. Tautan yang kosong tidak ditampilkan.
Tahap 4: Sprint 3, Panel Admin (UC-09 s.d. UC-13, UC-15)
Login dan logout (KF-11): token disimpan, halaman admin dialihkan ke login bila belum masuk, dan ada logout otomatis saat tidak aktif (KNF-10). Backend baru membatasi sesi 120 menit sejak login, jadi pelacak tidak aktif harus dibuat di frontend.
Ringkasan (KF-12): total produk, aktif/nonaktif, dan 5 produk terbaru.
Kelola produk (KF-13 s.d. KF-16):
Tabel produk dengan pencarian dan toggle aktif/nonaktif.
Form tambah/ubah (nama, kategori, harga, ukuran, deskripsi, foto, tautan Shopee) dengan validasi, pratinjau foto, dan batas JPG/PNG maks 2 MB.
Konfirmasi sebelum hapus.
Catatan teknis: ubah produk dengan foto memakai POST + _method=PUT.
Ubah konten profil (KF-20, Could): dikerjakan terakhir dan diturunkan lebih dulu kalau waktu mepet, sesuai SRS.
Tahap 5: Pengujian dan perbaikan (Minggu 13)
Tulis kasus uji dari kriteria penerimaan US-01 s.d. US-15 dan isi kolom “Kasus Uji” di matriks keterlacakan.
Uji lintas browser (Chrome, Edge, Firefox) dan lintas perangkat (HP, laptop) sesuai KNF-05.
Uji performa < 3 detik, uji login/hak akses/pembatasan login, dan test backend tambahan bila perlu.
UAT bersama pemilik toko, lalu perbaikan bug dari hasil UAT.
Tahap 6: Deployment
Backend di alwaysdata:
Ganti database dari SQLite ke MySQL, dan atur .env produksi (APP_DEBUG=false, FRONTEND_URL, SANCTUM_EXPIRATION).
Jalankan migration, storage:link untuk foto, dan seed admin. Ganti kata sandi bawaan AdminSeeder.
Frontend di Vercel: hubungkan ke repo, isi URL API produksi lewat environment variable, dan pastikan HTTPS.
Data awal: pemilik memasukkan produk asli dan konten profil, lalu hapus produk contoh.
Backup (KNF-04): siapkan cara export MySQL mingguan yang bisa dijalankan pemilik.
Tahap 7: Dokumen dan serah terima (Minggu 14-15)
User manual admin: login, tambah/ubah/hapus produk, ubah profil, backup.
Dokumen penerapan: arsitektur, cara deploy, daftar akun layanan.
Pelatihan pemilik dan BAST. Kredensial hosting diserahkan ke pemilik (KNF-07).
Bersihkan repo: rapikan tanicasual-app-lama dan file bawaan Laravel yang tidak dipakai, lalu rapikan README dan GitHub (KNF-06).

Selisih desain dan sistem
Galeri foto di Detail Produk. Desain menampilkan 3 thumbnail, sedangkan SRS dan backend hanya 1 foto per produk. Saya ikuti SRS (1 foto) dan thumbnail dihilangkan. Kalau mau galeri, itu change request dan perlu ubah backend.
Ukuran. Desain menampilkan chip S, M, L, XL. Form admin menyebut “Contoh: S, M, L, XL”, jadi cocok dengan kolom teks ukuran yang sudah ada. Frontend tinggal memecah teks per koma menjadi chip.
“Produk Unggulan” di Beranda. Backend tidak punya penanda unggulan, jadi saya tampilkan 4 produk terbaru.
Kategori tidak konsisten di desain. Filter katalog memakai Jaket, Sepatu, Celana, Topi, sementara dropdown form admin memakai Kaos, Kemeja, Celana, Aksesoris. Dropdown form admin perlu satu daftar yang sama dengan filter.
Ringkasan admin. Desain hanya menampilkan kartu “Total Produk” dan tabel produk terbaru. Data aktif/nonaktif dari API tidak dipakai.
